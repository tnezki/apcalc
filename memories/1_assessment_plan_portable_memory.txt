GENERIC MATH / SCIENCE ASSESSMENT PLAN PORTABLE MEMORY — v1.0
===============================================================

PURPOSE
=======

This portable memory builds or revises ONE unit assessment plan for a Math or Science course.
It is designed for the generic Math/Science course structure and is NOT for STEM courses.

The Assessment Plan is the first detailed unit-level contract downstream from the Course Framework.
It must give the later Bank build enough information to create the complete course content inventory:
practice, warm-ups, exit tickets, notes examples/You Try Its, formative assessments, summative assessment,
figures, and later spiral work.

This PM has TWO operating modes:

  MODE 1 — FULL BUILD
    Build one unit assessment plan from the Course Framework.

  MODE 2 — MAINTENANCE / REVISION
    Inspect an existing assessment plan, revise only what is required, preserve unaffected content,
    run the same QA, and return a complete replacement artifact.

The classroom is NOT required to follow a fixed Day 1 / Day 2 / Day 3 schedule.
The framework may describe a preferred instructional arc, but the Assessment Plan must treat demos,
investigations, notes, practice, activities, quizzes, discourse, and assessment as teacher-selectable options.
Readiness is expressed by SECTION, not by a fixed number of days.


===============================================================
PART 1 — SOURCE OF TRUTH AND INPUTS
===============================================================

SOURCE PRIORITY
---------------

1. THIS portable memory — structure, formatting, build, revision, and QA rules.
2. The uploaded Course Framework — course content, unit sequence, section sequence, terminology,
   standards/topics, pacing guidance, instructional philosophy, prerequisite information, and course-specific constraints.
3. An existing assessment plan — ONLY in Maintenance / Revision Mode.
4. User-requested changes in the current conversation.

Do not silently add outside standards, textbook sections, AP topics, NGSS codes, mathematical practices,
or course requirements that are not supported by the framework or explicitly requested by the user.
If the framework names a standard/topic system, preserve its terminology.

FULL BUILD — REQUIRED INPUTS
----------------------------

Required:
  1. This portable memory.
  2. The complete Course Framework.
  3. A request naming ONE unit to build.

Example:
  "Read the PM and framework, then build the Unit 2 assessment plan."

Do NOT require notes, bank, practice sets, activities, graph tool, or prior assessment plans.
The Assessment Plan is upstream from those resources.

MAINTENANCE / REVISION — REQUIRED INPUTS
----------------------------------------

Required:
  1. This portable memory.
  2. The existing assessment plan artifact that needs revision.
  3. The user's requested change.

Request the Course Framework ONLY when the requested change cannot be resolved reliably from the existing
assessment plan itself or when the user explicitly asks for framework realignment.

Never make the user reconstruct the original build session.
Ask only for genuinely missing information that is necessary to make the requested change correctly.

===============================================================
PART 3 — BUILD PHILOSOPHY
===============================================================

A. BUILD ORDER IS NOT A TEACHING CALENDAR
------------------------------------------

The course may have a preferred instructional arc such as:
  conceptual hook / prior knowledge -> instruction / notes -> investigation / modeling -> practice / discourse -> assessment

But the teacher may compress, expand, reorder, replace, or omit components because of:
  assemblies, snow days, reteaching, pacing, AP testing deadlines, student needs, shortened periods, quizzes, or other realities.

The Assessment Plan must therefore define:
  - what students need to learn,
  - what evidence would demonstrate learning,
  - when an assessment becomes eligible by SECTION,
  - what prerequisite/spiral knowledge should remain active,
without prescribing a fixed daily schedule.

B. DOK IS DESCRIPTIVE, NOT A QUOTA
-----------------------------------

Assign DOK based on the actual cognitive demand of the task.
Do not inflate DOK because of task length, vocabulary, number of steps, or an explanation prompt.
Do not manufacture DOK 3 or DOK 4 simply to fill a quota.

General interpretation:

  DOK 1 — recall, recognition, direct routine execution, reading a representation.
  DOK 2 — applying a concept/skill, translating representations, routine multi-step reasoning,
          interpreting or selecting a method when the path is reasonably clear.
  DOK 3 — strategic reasoning, non-routine method selection, critique, justification, comparison,
          constraint analysis, explanation of why, or synthesis across representations when reasoning is substantive.
  DOK 4 — extended/performance-oriented modeling, design, investigation, synthesis, or transfer across conditions.

DOK 4 should primarily live in PERFORMANCE EVIDENCE rather than ordinary question-bank problems.
DOK 3 may also be performance-oriented when that is the natural fit.
Conventional paper/digital questions should use DOK 3 or 4 only when the cognitive demand truly warrants it.

C. CURRENT / LAST / MASTERY IS A REQUIRED SPIRAL SYSTEM
--------------------------------------------------------

Every section must include a "Spiral Planning" block because the downstream Bank will create resources
using the Current / Last / Mastery pattern.

Definitions:

  CURRENT
    The learning target(s) and essential knowledge of the current section.

  LAST
    The immediately preceding section's learning that should remain active.
    For the first section of a unit, LAST may come from the prior unit's final section or an explicit prerequisite
    named by the framework.

  MASTERY
    Earlier prerequisite or previously taught learning that should continue to be retrieved across time.
    Mastery items should support long-term retention and transfer, not random review.

For every section provide:
  - Current Focus: one concise statement.
  - Last Focus: one concise statement.
  - Mastery Priorities: 2-4 concise prior skills/concepts when supported by the framework.

If the framework does not provide enough information to identify specific prior-course mastery content,
do not invent a detailed prior curriculum. Use broad prerequisite language supported by the framework,
such as "function notation and graph interpretation" or "measurement and proportional reasoning" only when the framework supports it.

D. ASSESSMENT PLAN MUST PREPARE THE BANK
----------------------------------------

The Bank will receive BOTH the Framework and the Assessment Plan.
The Assessment Plan must therefore make downstream content production easier by clearly identifying:

  - unit essential standard / enduring understanding,
  - section learning targets,
  - exactly 3 I-can statements per section,
  - important vocabulary/notation when central to evidence,
  - key representations,
  - likely misconceptions / failure points,
  - Current / Last / Mastery spiral priorities,
  - DOK-aligned evidence opportunities,
  - formative assessment families,
  - summative assessment priorities,
  - performance evidence that belongs outside conventional question sets.

Do NOT write actual bank questions in the Assessment Plan.
The next Bank PM will author those questions/tasks and figures.

PART 6 — ASSESSMENT PLAN CONTENT STRUCTURE
===============================================================

The HTML must contain these sections IN THIS ORDER:

  1. Course / Unit Header
  2. Essential Standard / Enduring Understanding
  3. Unit Source Alignment
  4. Section Outline — five section cards when the framework has five sections
  5. Unit Themes / Throughlines
  6. Learning Ladder
  7. Progress Tracking
  8. Assessment Methods by DOK Level
  9. Summative Assessment Plan
 10. Holistic Rubric

The plan ends after the Holistic Rubric.
Do not add a Bank section.
Do not add actual questions.
Do not add graphs.

If the framework has a different number of sections, preserve the framework rather than forcing five.
The generic course template is designed around five sections, but source truth wins for the course framework.


===============================================================
PART 7 — SECTION CARD REQUIREMENTS
===============================================================

Each section card must include:

A. Section number and title
B. Learning Target — preserve framework wording when provided
C. Exactly 3 I Can Statements
D. Key Vocabulary / Notation
E. Key Representations
F. Common Misconceptions / Failure Points
G. Modeling / Application Opportunities
H. Spiral Planning

I-CAN RULES
-----------

Exactly 3 per section.

I-cans must collectively cover the important learning target rather than force a mechanical verb quota.
Use natural, student-facing language.

Prefer strong verbs such as:
  analyze, apply, calculate, classify, connect, construct, critique, determine, distinguish,
  estimate, formulate, graph, interpret, justify, model, predict, represent, select, solve,
  translate, use, verify.

Do not artificially make every section contain modeling or justification if the content does not support it.
Do not inflate complexity to make an I-can sound advanced.

For MATH:
  Preserve precision in notation, representations, procedures, interpretation, reasoning, and strategy selection.

For SCIENCE:
  Preserve conceptual models, evidence, data/graphs, causal reasoning, quantitative relationships,
  system behavior, experimental interpretation, and scientific explanation as appropriate to the framework.

KEY VOCABULARY / NOTATION
-------------------------

List 3-8 items when genuinely important.
Do not force vocabulary for a section that is primarily procedural/representational.
Use framework terminology.

KEY REPRESENTATIONS
-------------------

List 3-6 important representations when appropriate.
Examples may include:
  equations, graphs, tables, diagrams, verbal descriptions, data sets, symbolic notation,
  particle models, force diagrams, circuit diagrams, geometric figures, rate tables, slope fields.

COMMON MISCONCEPTIONS / FAILURE POINTS
--------------------------------------

List 2-5 specific likely errors or misunderstandings that the future Bank should intentionally sample.
Prefer content-specific misconceptions over generic statements such as "students may make calculation errors."

MODELING / APPLICATION OPPORTUNITIES
------------------------------------

List 2-4 concise opportunities where the learning can be applied, modeled, interpreted, or connected.
These are possibilities, not required classroom days.

SPIRAL PLANNING
---------------

Use this exact internal structure:

  <h3>Spiral Planning</h3>
  <p><strong>Current Focus:</strong> ...</p>
  <p><strong>Last Focus:</strong> ...</p>
  <p><strong>Mastery Priorities:</strong> ...</p>

The future Bank uses this block to plan Current / Last / Mastery question inventory.

===============================================================
PART 9 — UNIT THEMES / THROUGHLINES
===============================================================

Create 4-6 unit-wide themes that the Bank and later resources should revisit.

  - representations that recur,
  - reasoning habits,
  - interpretation expectations,
  - modeling relationships,
  - use of units / notation,
  - evidence / data reasoning,
  - connections among sections.

These are unit throughlines, not activities.


===============================================================
PART 10 — LEARNING LADDER
===============================================================

Create an 8-rung learning ladder, highest to lowest.
The ladder describes progression of evidence, not a required sequence of daily instruction.

Use two rungs per DOK level:

  Rungs 8-7: DOK 4 — Above / Extended Performance
  Rungs 6-5: DOK 3 — Essential / Strategic Reasoning
  Rungs 4-3: DOK 2 — Essential / Application
  Rungs 2-1: DOK 1 — Essential / Foundational

IMPORTANT:
DOK 4 rungs should describe performance, modeling, design, investigation, or extended synthesis evidence.
They are not promises that ordinary worksheets or summative question sets must contain DOK 4 questions.

DOK 3 rungs should be genuinely strategic/non-routine.
Do not create DOK 3 merely by adding "explain" to a routine task.

Use the generic column heading:
  Practice Focus

Suggested practice-focus vocabulary:
  Representation, Modeling, Strategy, Reasoning, Justification, Communication,
  Interpretation, Precision, Data Analysis, Evidence, Experimental Reasoning, Transfer.

Do not invent formal MP/SEP numbers unless the framework explicitly provides or requests them.

===============================================================
PART 12 — ASSESSMENT METHODS BY DOK LEVEL
===============================================================

The generic course structure reserves 4 formative assessment families at each DOK level.
The Assessment Plan should propose four assessment ideas for each level, but the NATURE of those ideas must honor DOK.

This is NOT a demand that every later question bank contain equal numbers of DOK 1/2/3/4 questions.

DOK 1 — FOUNDATIONAL EVIDENCE
-----------------------------

Typical formats:
  brief proficiency check, recognition/classification, direct computation, vocabulary/notation check,
  reading a graph/table/diagram, short exit-style check.

Four ideas.
Each idea gets:
  - task name,
  - formative link,
  - Eligible After Section [#.#],
  - concise description,
  - what the evidence tells the teacher.

DOK 2 — APPLICATION EVIDENCE
----------------------------

Typical formats:
  multi-representation task, applied computation, short modeling setup, data interpretation,
  routine method selection, graph/table construction, compare representations where reasoning is moderate.

Four ideas.

DOK 3 — STRATEGIC / REASONING EVIDENCE
---------------------------------------

Typical formats:
  constructed response, non-routine strategy selection, critique, justification, theorem/condition reasoning,
  model comparison, constraint analysis, representation synthesis, short performance task.

Four ideas.
Do not default all four to error analysis.
Do not inflate routine questions to DOK 3 merely because students write a sentence.

DOK 4 — PERFORMANCE EVIDENCE
----------------------------

Typical formats:
  modeling performance task, investigation, design-and-test task, data/model synthesis,
  multi-condition analysis, extended transfer, critique-and-revise performance.

Four ideas.
These should primarily be PERFORMANCE TASKS, not ordinary test questions.
They may be brief classroom performance tasks rather than large projects.
They can support demos, investigations, discourse, modeling, or other extended evidence later.

FORMATIVE LINK PATTERN
----------------------

  ../../zssgrefwformativeassessments/unit_U_formative_assessments/u0U-dokD-N.html

  ../../zssgrefwformativeassessments/unit_2_formative_assessments/u02-dok3-4.html

TIMING LABEL
------------

Use:
  Eligible After Section [#.#]

Do not use fixed Day 1 / Day 2 / Day 3 labels.

PART 13 — SUMMATIVE ASSESSMENT PLAN
===============================================================

The summative section plans the future summative but does not write the questions.

Include:
  1. Link to the reserved summative file.
  2. Recommended timing based on the framework/course structure.
  3. Course-appropriate assessment format.
  4. Major evidence priorities.
  5. Representation / reasoning / interpretation expectations.
  6. Spiral statement.
  7. Clear statement that DOK 4 performance evidence normally lives outside the conventional summative question set.

Do not force "45-minute paper-only" unless the framework/user requires it.

For AP / externally tested courses:
  honor the framework's testing style, calculator expectations, notation, justification, or question families when supplied.
  Do not invent proprietary/restricted assessment content.

For conventional summatives:
  DOK 1-3 questions may be used when they naturally fit.
  DOK 4 is normally represented through separate performance evidence rather than forced into a conventional test item.

===============================================================
PART 14 — HOLISTIC RUBRIC
===============================================================

Use four levels:

  A — Highly Proficient
  B — Proficient
  C — Developing Proficiency
  Not Yet — Insufficient Evidence

Keep the rubric generic enough to work across Math and Science while making the FIRST SENTENCE of each level unit-specific.

Locked common language:

A — Highly Proficient
[UNIT-SPECIFIC FIRST SENTENCE.] Work is accurate, well-organized, and supported by clear reasoning. The student connects relevant representations, concepts, evidence, or models and communicates conclusions with precision and independence.

B — Proficient
[UNIT-SPECIFIC FIRST SENTENCE.] Most work is accurate, and the student can complete standard and moderately complex tasks independently. Reasoning and communication are generally clear, though they may lack some precision, flexibility, or depth.

C — Developing Proficiency
[UNIT-SPECIFIC FIRST SENTENCE.] The student can complete many routine tasks but may need support with reasoning, representations, notation, evidence, modeling, or multi-step problem solving. Work may contain errors or incomplete explanations, but there is sufficient evidence of developing understanding of the central ideas.

Not Yet — Insufficient Evidence
[UNIT-SPECIFIC FIRST SENTENCE.] Work shows major misconceptions, significant procedural or conceptual errors, weak reasoning, or difficulty connecting the representations, evidence, or models required by the unit. Additional instruction, practice, feedback, or reassessment may be needed before proficiency is demonstrated.

===============================================================
PART 19 — MODE 2: MAINTENANCE / REVISION
===============================================================

TRIGGER
-------

Use Maintenance / Revision Mode when the user says things such as:

  "I don't like the Unit 3 assessment plan. Rebuild it."
  "Change the I-can statements in 2.4."
  "The DOK 4 tasks in Unit 5 are too much. Fix them."
  "Replace the formative idea for DOK 3-2."
  "The spiral plan for 4.1 is wrong."
  "Update Unit 6 to match the framework better."

WORKFLOW
--------

1. Read this PM completely.
2. Inspect the existing assessment plan completely.
3. Identify the smallest requested change and all sections it logically affects.
4. Determine whether the Framework is actually needed.
   - If the existing plan contains enough authoritative information, proceed without asking.
   - If the change requires source realignment or missing upstream facts, ask only for the Framework.
5. Preserve everything not affected by the request.
6. Make the requested change.
7. Propagate internal dependencies inside the assessment plan.

Examples of internal propagation:
  - If a section learning target changes, check its I-cans, ladder, formative eligibility, summative priorities, rubric sentence, and spiral planning.
  - If a section is reordered, update Last Focus and any formative eligibility labels.
  - If a DOK classification changes, update the relevant DOK assessment idea and ladder language if necessary.
  - If a mastery priority changes, update only the affected Spiral Planning blocks unless broader alignment requires more.

8. Run all 8 QA passes.
9. Return the COMPLETE replacement assessment-plan HTML, not a patch or isolated snippet.
10. Briefly report what changed.

DOWNSTREAM IMPACT
-----------------

The Assessment Plan is upstream of the Bank and later resources.
If a revision would logically affect already-built downstream artifacts, report the impact succinctly.

Example:
  "This change alters the Section 3.4 Current Focus and DOK 3 formative intent, so the Unit 3 Bank/formative package should be regenerated when we reach that maintenance step."

Do NOT automatically rebuild downstream resources under this PM unless the user explicitly asks and provides the relevant downstream PM/artifacts.

MAINTENANCE DELIVERY
--------------------

Return the same artifact type as a full build:
  unit[#]_assessment_plan.html

Then report:
  - requested change,
  - sections changed,
  - internal dependencies updated,
  - downstream resources potentially affected,
  - QA result.

PART 20 — COMMON FAILURE MODES
===============================================================

1. Treating framework Day 1 / Day 2 / Day 3 language as a mandatory teaching calendar.
2. Building more than one unit when only one was requested.
3. Asking for notes/bank/practice files during a full assessment-plan build.
4. Inventing formal standards or topic codes not supplied by the Framework.
5. Forcing Math terminology into Science or Science terminology into Math.
6. Omitting Current / Last / Mastery spiral planning.
7. Treating Mastery as random old content instead of deliberate retrieval priorities.
8. Assigning DOK by verb alone.
9. Making a routine multi-step question DOK 3 simply because it has several steps.
10. Creating ordinary DOK 4 test questions just to satisfy a distribution.
11. Making all DOK 3 tasks error analysis.
12. Making DOK 4 a conventional worksheet category rather than performance evidence.
13. Writing actual Bank questions in the Assessment Plan.
14. Building graphs in the Assessment Plan.
15. Using old Algebra-only 45-minute paper-only summative language when the course framework indicates something else.
16. Hard-coding "Math Practice" in a Science plan.
17. Using MP or SEP codes without a source/request.
18. Missing formative links or wrong zero-padded formative unit token.
19. Wrong CSS depth.
20. Rebuilding the entire plan in Maintenance Mode when a targeted revision would preserve approved content.
21. Asking the user to re-upload every original build source for a small revision.
22. Returning a patch instead of the complete replacement HTML.
23. Failing to report downstream impact after changing an upstream plan.
24. Claiming QA PASS without running the checks.
