GENERIC MATH / SCIENCE NOTES BUILD - PORTABLE MEMORY v3
======================================================================

PURPOSE
======================================================================

This portable memory has TWO equal purposes.

PURPOSE 1 - FULL BUILD
Build a complete unit of student and teacher notes from the approved
upstream Assessment Plan and canonical Bank.

PURPOSE 2 - MAINTENANCE / REVISION
Repair, replace, revise, or rebuild one part of an existing notes
resource with the smallest necessary input, preserve everything the
user did not ask to change, run the same QA rules, and return the
complete updated replacement ZIP.

This PM is generic for:
  COURSE_FAMILY = MATH
  COURSE_FAMILY = SCIENCE

The same file/folder architecture is used for both course families.
Instructional content and representation choices branch naturally by
subject.

This PM assumes the course has already been built in this dependency
order:
  Framework -> Assessment Plan -> Bank -> Notes

The Notes build does NOT normally need the Framework again. The
Assessment Plan and Bank have already inherited the upstream alignment.

IMPORTANT PHILOSOPHY:
  Build order is not a classroom calendar.
  Notes are one instructional option in a rich course menu.
  Do not hard-code a teacher into a fixed Day 1 / Day 2 / Day 3 rhythm.

PART 2 - READ ORDER / BUILD MEANS BUILD
======================================================================

READ ORDER - COMPLETE BEFORE WRITING STUDENT HTML
----------------------------------------------------------------------

1. Read this PM completely.
2. Read the entire Unit Assessment Plan.
3. Read unit[#]_mapping.csv completely enough to understand all Notes
   Example/YTI routing and the required What's To Come routing for every
   section.
4. Read the complete What's To Come and Notes Example/YTI blocks in the
   Bank HTML for the unit.
5. Inspect every Bank figure referenced by those mapped items.
6. Read the Bank generate_graphs.py enough to locate the generation
   blocks for every reused Bank figure.
7. Read the uploaded authoritative graph_tool.py completely, including
   every public function signature and the FINAL append marker.
8. Complete the private UNIT NOTES PLAN and per-section CONTENT PLAN,
   including the explanatory-reading, theorem/formula/reference-block,
   and figure plan.
9. Only then write student HTML.
10. Create any Notes-specific explanatory graphs / diagrams that the
    instructional reading genuinely needs.
11. Run student QA.
12. Build teacher HTML from the final student HTML.
13. Run teacher/package QA.
14. Assemble the exact ZIP.

When the user says BUILD / CREATE / GENERATE / MAKE / COMPLETE NOTES,
execute the entire workflow. Do not stop after an outline or preview.

The ZIP is the normal endpoint.

PART 3 - COURSE-FAMILY BRANCH
======================================================================

DETERMINE COURSE FAMILY
----------------------------------------------------------------------

Prefer an explicit Assessment Plan declaration such as:
  Course Family: MATH
  Course Family: SCIENCE

If absent, infer only when the course is obvious. If genuinely
ambiguous, ask one short clarifying question.

MATH EMPHASIS
----------------------------------------------------------------------

Math notes should emphasize:
  - definitions and notation
  - symbolic structure
  - representation connections
  - equations / tables / graphs
  - worked reasoning
  - method selection
  - interpretation
  - justification
  - common algebraic/procedural misconceptions

Do not turn the reading into a dry procedure list. Explain why a method,
representation, theorem condition, or relationship works.

SCIENCE EMPHASIS
----------------------------------------------------------------------

Science notes should emphasize:
  - concepts and mechanisms
  - evidence and models
  - variables and relationships
  - diagrams / graphs / tables
  - observations vs. inferences when relevant
  - scientific explanation
  - quantitative relationships only when the Assessment Plan supports
    them
  - units, assumptions, and interpretation
  - common conceptual misconceptions

Do not force unnecessary calculation into conceptual science sections.

VISIBLE REFERENCE-BLOCK LABELS
----------------------------------------------------------------------

Use the existing CSS class math-notes for formal/reference blocks in
both course families. The class name is a legacy presentation class; the
VISIBLE label should match the purpose of the block.

  Math Notes

  Notation
  Method

SCIENCE labels may include:
  Model Notes
  Definition
  Relationship

Choose the clearest label. Do not force every formal block to be called
Math Notes or Model Notes.

======================================================================
PART 4 - READING LEVEL / INSTRUCTIONAL DESIGN
======================================================================

DEFAULT READING LEVEL
----------------------------------------------------------------------

Target an approximately 11th-grade reading level unless the user or
course materials clearly specify a different level.

This does NOT mean making prose artificially dense. Use mature, direct
academic language with:
  - correct discipline vocabulary
  - clear transitions and causal / logical connections
  - enough explanation to support independent rereading
  - explicit interpretation of equations, graphs, diagrams, and models
  - no unnecessary jargon
  - no childish simplification

For especially technical AP / advanced courses, preserve the exact
technical language students must learn.

GENERIC GOLD-STANDARD FLOW
----------------------------------------------------------------------

Use the Physics-style INTERLEAVED architecture for BOTH Math and Science,
but do NOT force every conceptual block into the same template.

Every section contains:

  Learning Target
      -> Vocabulary
      -> Preview / skim
      -> What's To Come  [REQUIRED EVERY SECTION]
      -> Content / instruction
           which may contain any purposeful combination of:
              * detailed reading passages
              * diagrams / graphs / images / tables
              * definition blocks
              * formula / relationship blocks
              * theorem / law / principle blocks
              * important-concept blocks
              * representation-comparison blocks
              * Stop and Discuss when discussion genuinely helps
              * Bank Example / Bank You Try It pairs
      -> Vocabulary Definitions
      -> Summary
      -> Common Mistakes

There is NO Exit Ticket in Notes. Exit Tickets are a separate course
resource and are built by their own PM.

INTERLEAVING RULE
----------------------------------------------------------------------

Do not put all explanatory reading first and all Bank practice at the
end. Use application during the development of the content.

A strong pattern is often:

  Detailed Reading / Representation
      -> optional Stop and Discuss
      -> Definition / Formula / Theorem / Important Concept block(s)
      -> Bank Example
      -> Bank You Try It
      -> More detailed Reading / Representation
      -> optional Stop and Discuss
      -> additional reference block(s)
      -> next Bank pair

However, this is a design pattern, not a rigid cycle quota.

REFERENCE BLOCKS DO NOT REQUIRE DISCUSSION
----------------------------------------------------------------------

A self-contained block whose main purpose is to state, organize, or
formalize content does NOT need a Stop and Discuss merely because it
appears in the notes.

Examples:
  - a vocabulary definition set
  - a formula with variable meanings and units
  - a theorem with hypotheses and conclusion
  - a law / principle
  - a method checklist
  - an important conceptual distinction
  - a notation reference
  - a representation summary

Use discussion only when students would benefit from interpreting,
comparing, predicting, critiquing, or explaining the content.

NUMBER OF APPLICATION PAIRS
----------------------------------------------------------------------

The Bank mapping controls the number and order of Notes Example/YTI
pairs.

Use every mapped pair exactly once and in order.
Do not invent an extra pair.
Do not drop a mapped pair merely to shorten the notes.

The number of reading passages / reference blocks does NOT have to equal
the number of Bank pairs. One application pair may follow several
instructional blocks, or one substantial reading passage may prepare
students for more than one related block before an application.

READING DENSITY - MORE DEVELOPED THAN A STUDY GUIDE
----------------------------------------------------------------------

Reading passages may be substantially longer and more detailed than in
prior Notes PMs.

For a normal substantial reading passage, a strong default is:
  - about 5 to 8 short-to-medium paragraphs
  - usually 2 to 6 sentences per paragraph
  - multiple representations embedded where they improve understanding
  - explicit explanation of WHY a relationship, method, theorem, model,
    or representation works
  - connections to prerequisite ideas and to what students will do next

A section may contain multiple substantial reading passages.
Shorter passages are appropriate when the content is mainly a theorem,
definition set, formula reference, or concise conceptual distinction.
Do not pad prose to meet a quota.

The finished notes should read like a coherent, illustrated instructional
text that students can learn from again later - not a short summary plus
worksheet questions.

ILLUSTRATED READING
----------------------------------------------------------------------

Reading may and often should include:
  - equations and symbolic derivations
  - formula / theorem boxes
  - tables
  - graphs
  - diagrams
  - models
  - annotated or neutral illustrations
  - multiple-representation comparisons

The visual or formula should appear where the prose needs it, not dumped
at the end of the section.

A figure used only for explanation may be created during the Notes build;
it does NOT have to be a Bank figure. See PART 7 for the distinction
between canonical Bank-task figures and Notes-specific explanatory
figures.


======================================================================
PART 5 - BANK-FIRST CONTENT RULES - NON-NEGOTIABLE
======================================================================

THE BANK IS THE CANONICAL SOURCE OF STUDENT TASKS
----------------------------------------------------------------------

Downstream Notes do NOT rewrite mapped Bank questions.

The following content is copied from the Bank VERBATIM in student
meaning, values, choice wording/order, tables, and canonical task-figure
intent:

  - Notes Examples
  - Notes You Try Its
  - What's To Come / Future Task

Allowed HTML normalization:
  - remove Bank-only metadata divs
  - remove visible Bank IDs
  - remove solution blocks from student HTML
  - convert destination-specific wrappers to Notes wrappers
  - remove a bank-only presentation class such as class="choices" while
    preserving the exact choices and order
  - keep table class="values"
  - preserve canonical Bank-task figure filename / visual exactly

Do NOT:
  - paraphrase a mapped Bank prompt
  - swap numbers
  - alter answer choice wording or order
  - change the requested representation
  - simplify a multi-part prompt
  - change DOK by adding/removing reasoning requirements

NOTES EXAMPLE / YTI ROUTING
----------------------------------------------------------------------

Use mapping rows with:
  destination_group = notes

Expected IDs:
  U[#]-S[#]-NOTE-EX01
  U[#]-S[#]-NOTE-YTI01
  ...

Use destination_slot to preserve exact pair order.

Student HTML:
  copy the student-facing problem/task only.

Teacher HTML:
  use the Bank solution / rationale in the workspace immediately after
  the task.

WHAT'S TO COME ROUTING - REQUIRED EVERY SECTION
----------------------------------------------------------------------

Every section MUST contain exactly one canonical What's To Come task.

Expected ID:
  U[#]-S[#]-WTC01

Required mapping:
  destination = whats_to_come
  destination_group = notes
  destination_slot = WTC01

Do NOT use PERF01 as an automatic substitute. Performance tasks and
What's To Come are separate Bank destinations.

The student does NOT solve WTC01 here. The purpose is long-range
annotation, noticing, and anticipation.

If a section does not contain its mapped WTC01:
  STOP before building that section and report the missing Bank routing
  as a BANK MAINTENANCE issue.

Do NOT silently omit What's To Come.
Do NOT invent a Notes-only replacement when the canonical Bank item is
missing.

ASSESSMENT SECURITY
----------------------------------------------------------------------

Never pull student-facing content from:
  - formative assessment destination blocks
  - summative assessment destination blocks
  - assessment-only figures

into instructional Notes.

The Bank deliberately created unique assessment items. Preserve that
separation.

The explanatory reading may teach the concept, but must not reproduce or
effectively solve a future formative/summative item.

DISCUSSION PROMPTS ARE NOT BANK ITEMS
----------------------------------------------------------------------

Stop-and-Discuss prompts are instructional processing questions, not
assessment-bank questions.

They may be authored during the Notes build because their purpose is to
send students back to the reading, notation, evidence, diagram, theorem,
model, or representation they just studied.

Keep them discussion-oriented and use them only when they improve the
instructional flow.


======================================================================
PART 6 - WHAT'S TO COME CONTRACT
======================================================================

EVERY SECTION HAS ONE
----------------------------------------------------------------------

What's To Come is a required feature of every Notes section.

Its purposes are to:
  - preview a meaningful future application / performance task
  - give students a reason to notice today's definitions, formulas,
    theorems, representations, or concepts
  - support long-range annotation and metacognition
  - create continuity across the section without requiring students to
    solve future material early

SOURCE
----------------------------------------------------------------------

The task comes from the canonical Bank What's To Come routing.
Use the section's required WTC01 item.

Copy the student-facing task body verbatim.
Do not copy Bank metadata or solution notes into student HTML.
Retain data-source-id for traceability.

STUDENT DIRECTIONS
----------------------------------------------------------------------

Students should NOT solve the task at the beginning of the notes.
They annotate what they know, what looks familiar, what is new, and what
ideas or representations they expect to need later.

The teacher file may include facilitation notes in the What's To Come
workspace, but it should not fully solve the future task.

MISSING TASK
----------------------------------------------------------------------

Because every section requires What's To Come, a missing mapped task is
not permission to omit the feature.

Treat it as a Bank maintenance problem:
  1. identify the missing section / expected WTC01 destination
  2. request the current Bank PM/package only if needed
  3. create/fix the canonical Bank WTC01 first
  4. then rebuild Notes from that canonical item


======================================================================
PART 7 - FIGURES / GRAPH TOOL / NOTES-SPECIFIC VISUALS
======================================================================

TWO FIGURE CATEGORIES
----------------------------------------------------------------------

A. CANONICAL BANK-TASK FIGURES
   Figures attached to mapped Bank Examples, YTIs, or What's To Come
   tasks are authoritative Bank assets.

B. NOTES-SPECIFIC EXPLANATORY FIGURES
   Figures created only to teach or illustrate content in the reading,
   theorem/formula/reference blocks, or representation explanations.
   These may be created during the Notes build.

Do not confuse the two categories.

A. BANK-TASK FIGURES - REUSE EXACTLY
----------------------------------------------------------------------

For every Bank item used in Notes:
  1. Read figure_files in unit[#]_mapping.csv.
  2. Confirm the figure reference in the Bank HTML item.
  3. Copy the exact PNG(s) from Bank figures/ into the section Notes
     figures/ folder.
  4. Preserve the filename exactly.
  5. Preserve neutral / non-answer-revealing visual intent.

Do not redraw, relabel, or restyle a canonical Bank-task figure in Notes.
Only copy figures needed by the Notes section.
Never copy formative/summative-only figures into student Notes.

B. NOTES-SPECIFIC EXPLANATORY FIGURES - MAY BE CREATED HERE
----------------------------------------------------------------------

The Notes build MAY create additional figures when they materially
improve the explanation.

Examples:
  - a graph illustrating a theorem condition
  - a diagram showing how quantities are related
  - a sequence / before-after illustration
  - a labeled teacher-explanation model that does NOT answer an upcoming
    student task
  - a comparison of two representations
  - a context diagram supporting a formula
  - a visual definition

For a graph or visual type supported by graph_tool.py:
  MUST use the uploaded authoritative graph_tool.py.

For a non-graph explanatory diagram that graph_tool.py does not support:
  use the available image-generation / diagram capability to create a
  clear instructional image and save it in figures/.

Notes-specific explanatory visuals are allowed because they are teaching
assets, not canonical Bank student tasks.

ANSWER-SECURITY RULE
----------------------------------------------------------------------

A Notes-specific explanatory figure must not reveal the answer to an
upcoming Bank Example/YTI or a future assessment item.

Use a different neutral example, generic case, or explanatory model when
necessary.

GENERATE_GRAPHS.PY - REQUIRED IN EACH SECTION FOLDER
----------------------------------------------------------------------

Each section folder must contain:
  generate_graphs.py
  figures/

Construct generate_graphs.py as follows:

  1. Copy the currently uploaded authoritative graph_tool.py in full,
     byte-for-byte.
  2. Find the FINAL authoritative append marker.
  3. For reused Bank graphs, locate the exact relevant generation blocks
     in the Bank package and append them unchanged.
  4. For new Notes-specific graphs that graph_tool.py supports, append
     new generation calls after the FINAL marker using only existing
     public graph-tool functions and valid parameters.
  5. Do not modify graph_tool.py source lines.
  6. Do not add style overrides or replacement helper functions.
  7. Run generate_graphs.py.
  8. Verify every referenced generated PNG exists.

If the section has no graph-tool figures:
  still include generate_graphs.py as a verbatim copy of the uploaded
  graph_tool.py with no appended generation calls.

The figures/ folder may contain:
  - copied canonical Bank-task PNGs
  - Notes-specific graph-tool PNGs
  - Notes-specific generated explanatory diagrams/images

FIGURE TRACEABILITY
----------------------------------------------------------------------

In the private plan / QA log, identify each figure as:
  BANK-TASK
  NOTES-GRAPH
  NOTES-DIAGRAM

This makes later maintenance clear.

GRAPH TOOL MISMATCH
----------------------------------------------------------------------

If a canonical Bank generation block depends on a function not present
in the currently uploaded graph_tool.py:
  STOP and report the mismatch.
Do not patch the canonical tool inside the Notes build.

PART 11 - REQUIRED SECTION SEQUENCE
======================================================================

Every section follows this overall order:

  1. TITLE
  2. LEARNING TARGET
  3. VOCABULARY - terms only
  4. PREVIEW - skim / vocabulary sort / noticed-predict-wonder
  5. WHAT'S TO COME - REQUIRED
  6. CONTENT HEADER
  7. INSTRUCTIONAL BODY - flexibly interleaved
       May include:
         a. detailed Reading / instruction passages
         b. graphs / diagrams / tables / images / equations
         c. Stop and Discuss where useful
         d. Definition blocks
         e. Formula / Relationship blocks
         f. Theorem / Law / Principle blocks
         g. Important Concept / Notation / Method blocks
         h. canonical Bank Example + workspace
         i. canonical Bank You Try It + workspace
       Use every mapped Bank Example/YTI pair exactly once and in order.
       Do not require one S&D for every reference block.
  8. VOCABULARY DEFINITIONS
  9. SUMMARY + summary workspace
 10. COMMON MISTAKES

There is NO Exit Ticket in Notes.
Exit Tickets are built separately.

Do not put all reading first and all practice later.
Do not insert an automatic Stop and Discuss after a YTI.
Do not insert a Stop and Discuss after a definition/formula/theorem block
unless discussion genuinely adds instructional value.

======================================================================
PART 13 - READING CONTENT RULES
======================================================================

WHAT READING MAY BE AUTHORED FROM
----------------------------------------------------------------------

Reading is authored from:
  - exact Assessment Plan Learning Target / I-cans
  - Key Vocabulary / Notation
  - Key Representations
  - Common Misconceptions
  - Modeling / Application Opportunities
  - Notes Example/YTI concepts and Bank solutions
  - approved Bank-task figures when safe to reuse instructionally
  - Notes-specific explanatory figures created for instruction
  - optional user-supplied content sources if provided

The Bank solutions may inform explanatory accuracy, but do not copy a
solution sentence in a way that gives away the upcoming exact Example or
YTI.

DEPTH / LENGTH EXPECTATION
----------------------------------------------------------------------

The reading is not a brief bridge between questions. It is instructional
content in its own right.

For a major concept, explain as much of the following as naturally fits:
  - what the idea means
  - why it matters
  - how it connects to prior knowledge
  - how to recognize it
  - conditions / assumptions / limitations
  - how representations encode the idea
  - what changes and what stays invariant
  - why a common misconception fails
  - how the idea prepares students for later work

A strong substantial reading passage commonly uses 5-8 paragraphs and
may include multiple figures / equations / tables. A section may contain
multiple such passages.

Do not artificially shorten complex AP / advanced material merely to
keep the notes compact.
Do not add filler when a concise theorem/definition/reference block is
better.

READING MAY INCLUDE FORMAL BOXES
----------------------------------------------------------------------

A reading passage may be interrupted by a formal Definition, Formula,
Theorem, Law/Principle, Important Concept, or Model block and then
continue afterward.

This is encouraged when it improves clarity.

Example flow:
  prose explaining the need for a theorem
      -> Theorem block with hypotheses / conclusion
      -> prose interpreting why the conditions matter
      -> explanatory graph
      -> application

READING MUST PREPARE, NOT PRE-SOLVE
----------------------------------------------------------------------

Before each Bank Example/YTI pair, explain the concept or method in a
different representation, generic case, or neutral example.

Avoid reusing the exact:
  - numbers
  - context
  - table values
  - graph features
  - answer choices
  - final conclusion

from the upcoming Bank item in the reading immediately before it.

The student should still have to solve the Bank task.

VOCABULARY BOLDING
----------------------------------------------------------------------

Inside instructional reading-box prose:
  - bold a vocabulary term only at its FIRST meaningful introduction
    and/or definition
  - if it appears incidentally earlier, wait until the meaningful intro
  - do not repeatedly bold it later
  - do not bold ordinary emphasis in reading prose

The term may be bold again in the final vocabulary definition table.
Reference/formalization blocks may use <strong> for structural labels
such as Conditions, Conclusion, Units, or Key idea.

STOP AND DISCUSS - PURPOSEFUL, NOT AUTOMATIC
----------------------------------------------------------------------

Stop and Discuss is OPTIONAL per reading chunk.

Use it when students benefit from:
  - returning to evidence
  - interpreting a graph / diagram / table
  - comparing representations
  - explaining theorem conditions
  - making a prediction
  - critiquing a claim
  - articulating a conceptual distinction

Do NOT use it merely because:
  - a definition was stated
  - a formula was boxed
  - a theorem was listed
  - a reference table appeared
  - a You Try It ended

When used, most S&D blocks contain 2-3 concise prompts and at least one
prompt should require students to return to a specific sentence,
equation, table, graph, diagram, model, or comparison.


======================================================================
PART 14 - REPRESENTATION RULES
======================================================================

MATH REPRESENTATIONS
----------------------------------------------------------------------

When the section naturally uses multiple representations, deliberately
connect them.

Possible artifacts:
  - MathJax equation / symbolic rule
  - table.values
  - graph
  - explanatory diagram
  - verbal interpretation
  - context sentence
  - theorem / condition box

Examples:
  - function value: equation + table + graph meaning
  - limit: notation + graph/table behavior
  - derivative: symbolic notation + slope/rate interpretation
  - integral: area/accumulation + symbolic notation + units
  - theorem: hypotheses + conclusion + representation showing why
    conditions matter

Do not force all representations into every block.
Use what serves the concept.

SCIENCE REPRESENTATIONS
----------------------------------------------------------------------

Possible artifacts:
  - variable / unit table
  - equation relationship
  - graph
  - data table
  - evidence/model diagram
  - explanatory illustration
  - verbal mechanism
  - observation/inference organization
  - law / principle / model box

Use equations as relationships/models first when that fits the course.
Do not exceed the Assessment Plan's intended quantitative depth.

FORMULAS / THEOREMS / LAWS / IMPORTANT CONCEPTS
----------------------------------------------------------------------

Formal content should be visually easy to find when students return to
the notes later.

Use a reference block when appropriate and include the information a
student actually needs, such as:
  - formal statement
  - hypotheses / conditions
  - variable meanings
  - units
  - domain restrictions
  - interpretation
  - when / why it applies
  - a concise neutral example

Do not reduce a theorem to a name alone.
Do not present a formula without explaining its quantities when those
meanings are not already secure.

ANSWER-REVEALING FIGURES
----------------------------------------------------------------------

Never add labels, captions, annotations, highlighting, or diagram
features that reveal what the student is supposed to identify, classify,
infer, critique, or calculate in an upcoming Bank task or assessment.

A Notes-specific explanatory figure can be fully labeled when its sole
purpose is teaching a different neutral example.

======================================================================
PART 21 - MAINTENANCE / REVISION MODE - PURPOSE 2
======================================================================

TRIGGER
----------------------------------------------------------------------

Use Maintenance / Revision Mode when the user says things such as:

  "I don't like the notes for 3.4. Rebuild them."
  "Reading 2 is too wordy."
  "The explanation before Example 3 is confusing."
  "The graph is too small."
  "Replace Example 2."
  "The teacher answer is wrong."
  "Fix the vocabulary section."

GOAL
----------------------------------------------------------------------

Make the smallest aligned change, preserve everything unrelated, and
return a complete replacement package.

Never make the user reconstruct the original build session.

MINIMAL-INPUT RULE
----------------------------------------------------------------------

Inspect what the user provides FIRST.
Ask only for genuinely missing authoritative sources.

If the user provides an existing Notes ZIP, recover from it:
  - section number/title
  - Learning Target / I-cans
  - data-source-id Bank IDs
  - figure filenames
  - student/teacher structure
  - current wording/layout

Then determine what else is actually necessary.

REVISION CLASSIFICATION
----------------------------------------------------------------------

A. NOTES-LEVEL REVISION
Examples:
  - reading wording
  - paragraph density
  - vocabulary explanation
  - Stop and Discuss prompt
  - Math Notes / Model Notes explanation
  - Summary
  - Common Mistakes
  - teacher facilitation note
  - Notes-specific explanatory graph / diagram
  - figure placement / width class

These can normally be revised in the Notes package without changing the
Bank, provided the Learning Target and mapped canonical tasks remain
unchanged.

B. BANK-DERIVED CONTENT REVISION
Examples:
  - replace Example 2 question
  - change You Try It 3 numbers
  - alter future PERF task
  - alter a canonical Bank-task figure itself

Do NOT silently edit the Notes copy.
The canonical Bank must change first.

If the current Bank package + Bank PM are available, revise the Bank
first, then propagate the revised item verbatim into Notes.

If they are not available, ask only for the current unit Bank package
and the Bank PM needed to make the canonical change.

C. ASSESSMENT-PLAN ALIGNMENT REVISION
Examples:
  - Learning Target is wrong
  - I-can changed
  - section scope changed

Ask for the current Assessment Plan if it is not already available.
Do not invent a new target inside Notes.

D. FIGURE / DIAGRAM REVISION
Examples:
  - figure should be wider/narrower
  - move figure closer to related paragraph
  - explanatory reading needs a new graph
  - an existing Notes-specific diagram is unclear

If the figure is a canonical BANK-TASK figure, preserve the asset and
change only placement/width unless Bank maintenance is requested. Do not
redraw the canonical task figure inside Notes.

If the figure is NOTES-GRAPH or NOTES-DIAGRAM, it is a Notes-level
asset and may be revised/rebuilt during Notes maintenance using the same
figure rules in PART 7.

MAINTENANCE WORKFLOW
----------------------------------------------------------------------

1. INSPECT
   Open the existing Notes package completely enough to locate the
   requested section/block and its dependencies.

2. TRACE
   For any Bank-derived item, read data-source-id and trace it through
   mapping to the canonical Bank item.

3. CLASSIFY
   Decide A / B / C / D above.

4. PRESERVE
   Keep all unrelated sections and unrelated blocks unchanged.
   When practical, preserve untouched files byte-for-byte.

5. REVISE
   Make the smallest authoritative change.

6. PROPAGATE
   If a Bank item changed, update every supplied Notes occurrence of that
   Bank ID verbatim.

7. TEACHER SYNC
   Update teacher support wherever the changed student content affects
   an answer, rationale, misconception note, or follow-up.

8. FIGURE SYNC
   Copy/regenerate only affected figures. Do not regenerate unrelated
   figures merely because the ZIP is being rebuilt.

9. QA
   Run the relevant full-build passes plus complete package integrity.

10. DELIVER
   Return a complete replacement ZIP, not a loose HTML snippet.

DELIVERY SCOPE
----------------------------------------------------------------------

If the user gave a whole-unit Notes ZIP:
  return the whole updated unit ZIP unless they explicitly request only
  a section patch.

If the user gave only one section package:
  return u[unit]_[section]_notes.zip.

Briefly report:
  - section/block changed
  - Bank IDs changed, if any
  - whether Bank maintenance was required
  - affected figure(s), if any
  - QA result
